# Running CORA: what's needed and where to put it

## What's blocking us

Only **base MATLAB R2020b** is licensed on this machine. CORA's
constrained-zonotope operations — the ones that matter for our comparison —
call `linprog` and `optimoptions`, which live in the **Optimization Toolbox**.

Check what's installed:

```matlab
~/MATLAB/R2020b/bin/matlab -batch "v = ver; for k=1:numel(v); fprintf('%s\n', v(k).Name); end"
```

Right now that prints one line: `MATLAB`.

## Step 1 — check whether the licence already covers it

```matlab
~/MATLAB/R2020b/bin/matlab -batch "disp(license('test','Optimization_Toolbox'))"
```

`1` means the licence permits it and only the files are missing (easy).
`0` means the licence itself doesn't cover it (needs the admin who manages the
Vanderbilt site licence). Most university TAH licences **do** include
Optimization Toolbox.

## Step 2 — install it

Easiest route, if the licence covers it:

1. Launch MATLAB normally (`~/MATLAB/R2020b/bin/matlab`).
2. **Home → Add-Ons → Get Add-Ons**, search *Optimization Toolbox*, install.

If the Add-On Manager refuses, re-run the MathWorks installer with your account
and tick Optimization Toolbox in the product list.

Verify:

```matlab
~/MATLAB/R2020b/bin/matlab -batch "which linprog; disp(exist('optimoptions'))"
```

Both should resolve. `exist('optimoptions')` should print `2` or `5`.

## Step 3 — put CORA somewhere permanent

It is currently in `/tmp/cora`, which gets wiped. Please move it:

```bash
git clone --depth 1 https://github.com/TUMcps/CORA.git ~/tools/CORA
```

`~/tools/CORA` is the assumption in our scripts; any stable path works if you
tell us. It is ~52 MB and needs no build step.

## Step 4 — tell us it's ready

Then this should run:

```bash
cd COLLAB/experiments/geofence/cora
~/MATLAB/R2020b/bin/matlab -batch "addpath(genpath('~/tools/CORA')); addpath(pwd); geofence_cora(20, 0.8)"
```

`geofence_cora.m` is already written and reads the same CROWN contracts the
compositional encoding uses (`/tmp/cora_contracts.csv`, regenerated by
`compare.py`), so the comparison is like-for-like.

## What we lose if this can't be installed

Not much, but not nothing. `conzono.py` already implements constrained zonotopes
directly with an exact scipy LP, and it fails on the geofence exactly as every
other baseline does. What CORA would add is that the result is measured against
**the field's reference implementation** rather than against our own code —
which matters because a reviewer will ask, and because we have already been
caught once overselling a homemade baseline.
